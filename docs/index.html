Idea

01 / 06

One resolver call. A useful answer.

DNS normally answers what address is this name. DNSi uses the same lookup to deliver a short internal instruction, a prepared answer, or a utility result. The server can call an OpenAI-compatible model, but prepared knowledge and deterministic tools work without one. 

$ npm i -g @omodaka/dnsi
$ dnsi-ask --tool time
2026-11-22T10:23:15.832Z

$ dnsi-ask --tool hash hello
2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824

$ dnsi-ask --tool uuid
3f2b8c1e-9d4a-4e7b-b2c1-8a5f6e9d0c3a

$ dnsi-ask "what is dnsi"

Scope

02 / 06

Built for machines with only a resolver.

The primary use is short, self-hosted knowledge and utilities for constrained devices. No custom DNSi client is needed. Compatible DNS resolution must be available; this is not a promise to bypass network policy.

SituationWhat happens
Devices and internal knowledge
#iotShort answers without an HTTP client. Serve a maintenance instruction, prepared answer, or small utility result to compatible firmware through its existing resolver.
>classesPLCs, printers, sensors, set-top boxes, routers. If it ships gethostbyname, it is a DNSi client (see AGENTS.md).
ttoolsFour small utilities. time, echo, uuid, hash answer in process. Time and UUIDs cross the network without authentication; never use them as trusted security inputs.
:clientlessdig, nslookup, Python, C, BusyBox. If it can resolve a name, it is already a DNSi client.
Other ways to run it
kknowledgeInternal runbooks. Serve prepared answers from your own LAN. Only publish information that may travel in observable DNS queries.
$terminalA CLI is included. Ask from a shell when that is convenient, but the differentiator is devices that cannot run normal application clients.
aagentsControlled experiments. Use DNSi only where DNS tool access is explicitly allowed. The server does not log per-user queries; resolvers and network controls may.
*tokensOpen and token-protected zones. One server, many zones. A token limits access and cost; it does not provide confidentiality.
 
/* the complete IoT client: no SDK, no TLS stack, no JSON parser */

Deploy

03 / 06

Run your own in two minutes.

Install the package, start the server, ask it. Everything below uses the published npm package - no clone needed. OPERATIONS.md covers every environment variable and a full public-deployment checklist.

WhereWho can askGood forCost
localYour machineonly youprotocol experiments, trying it outfree
lanYour networkeveryone on itteam knowledge, device fleetsfree plus AI tokens
publicA VPS on port 53anyone, or token holderspublic utility, paid serviceabout $5/month plus tokens
 
# 1. install (needs Node 22+)
npm install -g @omodaka/dnsi

# 2. ask the public instance - no setup at all
dnsi-ask "what is dnsi"
dnsi-ask --tool time

# 3. run YOUR OWN server on this machine (demo mode, no key)
dnsi-server            # serves zone dnsi.test on 127.0.0.1:5353

# 4. ask your own server
dnsi-ask "how do I split a git commit" --local

Prefer cloning? git clone then pnpm install && pnpm start runs the same server from source. Point it at any OpenAI-compatible endpoint with three environment variables for live model answers; without them it runs the local echo demo. Set DNSI_ANSWERS for prepared answers. Full deployment guide: OPERATIONS.md.

04 / 06

What it costs.

The expensive part is the model, and caching is the whole defence.

ScaleWhat you pay
localFree. No API key, no internet, no account. Try everything before you spend anything.
hobbyUnder $10/month. A small VPS plus roughly $1 to $5 of tokens for a thousand questions a day.
repeatFree after the first ask. Answers are cached, canonical ones for an hour, so popular questions cost nothing.
toolsNever the model. Time, UUID and hash are computed in process; the cache holds them at no token cost.

Honest

05 / 06

Is this a hack?

It is a deliberate repurposing of the internet's oldest question-answering machine, built with the controls a security team would ask for before you deploy it.

ControlEnforced
amplificationReply capped at 1232 B, or the smaller size the requestor advertises. Classic clients get 512 with TC set and retry over TCP, which is not spoofable.
abusePer-client token bucket, on by default, plus in-flight load shedding. An unthrottled public nameserver is the failure mode this project is designed against.
server loggingNo per-user logs in this process. Only a startup line. Recursive resolvers, networks, and infrastructure outside this process may still log queries.
transportTCP-only mode for deployments that want no UDP surface at all.
supplyZero runtime dependencies. The DNS wire format is hand-written and unit-tested; three dev dependencies, lockfile committed.

Four honest limits.

Ordinary resolver lookups are plaintext. Do not send passwords or confidential knowledge. DoT/DoH to DNSi does not encrypt a legacy device's separate path to its resolver.

Tokens restrict access and cost; they are not secrets in transit. DNS-provided time and UUIDs are unauthenticated utilities, not trusted security primitives.

Compatible DNS resolution is required. Some networks restrict destinations, names, or record types; use DNSi only with authorization.

A single question is short. Longer ones are split into parts automatically; this is not for pasting documents.

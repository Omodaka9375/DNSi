Idea

01 / 06

Directory assistance, taught a new trick.

You dial a number, say a name, and a person tells you the answer. The internet has had that service since 1983. It is called DNS, and until now it knew exactly one kind of answer: what number is this name. DNSi adds a second one. The question travels inside the name, and the answer comes back in the reply. 

$ npx dnsi-ask "what is dnsi"
A question box that rides on DNS: ask by name, get the answer back as TXT records.

related:
  dig TXT what-is-dnsi-history.ask.dnsi.dev
  dig TXT who-is-dnsi-for.ask.dnsi.dev

$ npx dnsi-ask --tool time
2026-11-22T10:23:15.832Z
$ dig +short TXT what-is-dnsi.ask.dnsi.dev
"A question box that rides on DNS: ask by name, get the answer"
 "back as TXT records."

$ dig +short TXT tool.time.ask.dnsi.dev
"2026-11-22T10:23:15.832Z"
/* the complete client: gethostbyname returns the answer bytes */
struct hostent *h = gethostbyname("what-is-dnsi.ask.dnsi.test");
/* h->h_addr_list = UTF-8 answer, 4 bytes per address */
>>> import socket
>>> _, _, addrs = socket.gethostbyname_ex("what-is-dnsi.ask.dnsi.test")
>>> print(bytes(int(o) for a in addrs for o in a.split(".")))
b'A question box that rides on DNS: ...'
live: resolve from this page over DNS-over-HTTPS
The public instance answers here the moment dnsi.dev is live. Until then: run your own (window 1 above) and ask it over your LAN.

Related questions come back as CNAME records, so one answer is also a pointer into a graph. Every one of them is a name you can ask again with the same single call.

Scope

02 / 06

What people use it for.

Not a chat client. It is the one channel a locked-down machine still has open, and it needs no client at all.

SituationWhat happens
You
$terminalOne command, no browser. You live in a shell; the answer lands in it. No window, no login, no tab.
!blockedHostile networks. Hotel wifi, airplane wifi, locked-down offices. They block apps and sites; DNS stays open or nothing loads at all.
oofflineLocal first. Run it on your own machine and the demo answers need no key and no internet.
Devices (IoT)
#iotAnything with a resolver. A clock, a UUID, a hash and AI answers for a printer, a sensor, 20-year-old firmware - no crypto lib, no HTTP client, no firmware update.
>classesPLCs, printers, sensors, set-top boxes, routers. If it ships gethostbyname, it is a DNSi client (see AGENTS.md).
ttoolsFour built-ins. time, echo, uuid, hash answer locally in microseconds, never touching the model.
:clientlessdig, nslookup, Python, C, BusyBox. If it can resolve a name, it is already a DNSi client.
Teams and agents
kknowledgeOne place to ask. "How do I connect to the vpn" becomes a name anyone in the office can look up. IT writes it once.
aagentsSanctioned channel. A sandboxed agent that may only resolve DNS gets a question channel and a tool channel, rate limited and log-free.
*tokensOpen and private zones at once. One server, many zones. A zone can require a token inside the name; wrong or missing is refused.

Same code, same protocol. Only the reach and the cost change.

# window 1 - the server, no configuration needed
pnpm install && pnpm start

Point it at any OpenAI-compatible endpoint with three environment variables to get live model answers. With none set, it serves prepared answers about itself.

Honest

05 / 06

Is this a hack?

It is a deliberate repurposing of the internet's oldest question-answering machine, built with the controls a security team would ask for before you deploy it.

ControlEnforced
amplificationReply capped at 1232 B, or the smaller size the requestor advertises. Classic clients get 512 with TC set and retry over TCP, which is not spoofable.
abusePer-client token bucket, on by default, plus in-flight load shedding. An unthrottled public nameserver is the failure mode this project is designed against.
privacyZero per-user logging. One startup line, nothing else. No question is written anywhere.
transportTCP-only mode for deployments that want no UDP surface at all.
supplyZero runtime dependencies. The DNS wire format is hand-written and unit-tested; three dev dependencies, lockfile committed.

Two honest limits.

Questions and answers travel in plaintext DNS. Do not send passwords through it.

A single question is short. Longer ones are split into parts automatically; this is not for pasting documents.
